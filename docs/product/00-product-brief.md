# 00. Product Brief

## Сегмент

**B2B2C — книжные клубы при публичных (городских/районных) библиотеках.**

- **B2B-клиент (платящий):** библиотека. Покупает SaaS-подписку за аналитику, снижение нагрузки на библиотекарей и удержание читателей.
- **B2C-пользователь (бесплатный):** читатель 18–55 лет, приходит по внутренней мотивации, участвует в клубах, пользуется AI-компаньоном.

Школьные, вузовские и корпоративные библиотеки — Phase 2–3 (см. `01-personas.md`, `07-non-goals-and-risks.md`).

## Jobs-to-be-Done

| Actor | Job |
| --- | --- |
| Читатель | «Помоги мне понять, что читать дальше, и не бросить книгу на середине» |
| Читатель-клубник | «Дай мне тему и вопросы для обсуждения, чтобы клуб не превращался в светский вечер» |
| Библиотекарь | «Автоматизируй рутину (напоминания, подбор, модерация), чтобы я занимался людьми, а не таблицами» |
| Администратор библиотеки | «Покажи цифрами, что клубы и AI-инструменты удерживают читателей и оправдывают подписку» |

## Ценностное предложение

**Не «ещё один каталог с рекомендациями», а AI-компаньон читателя:**

1. **Q&A по текущей книге без спойлеров** — читатель спрашивает AI про книгу, которую читает прямо сейчас, и получает ответ, ограниченный прочитанной частью.
2. **Объяснение рекомендаций** — не «вам может понравиться», а «я предложил эту книгу, потому что вы дочитали X до главы Y и оценили Z».
3. **AI-вопросы для обсуждения в клубе** — куратор получает готовые вопросы по книге, привязанные к сюжету и темам.

Для библиотеки: **аналитика читательского поведения** (какие книги бросают, какие темы удерживают, какие рекомендации конвертируются в выдачу) на базе сигналов, собираемых платформой.

## North Star Metric

> **AI-сессии на активного читателя в неделю (AI-sessions per weekly active reader, ASPWAR)**

«AI-сессия» — любой цикл: читатель задал вопрос / запросил рекомендацию / открыл companion по книге → AI ответил → читатель взаимодействовал с ответом (кликнул книгу, сохранил в wishlist, поблагодарил, задал follow-up).

### Supporting метрики (3–5)

| Метрика | Зачем |
| --- | --- |
| **Wishlist → Loan conversion** | Показывает, что рекомендации конвертируются в реальные выдачи |
| **Club MAU / total readers** | Социальный липкий слой; без клубов продукт — «ещё один каталог» |
| **D30 retention читателя** | Выживает ли интерес после novelty |
| **Librarian WAU / total librarians** | Adoption внутри B2B-клиента; без библиотекаря клубы не живут |
| **Time-to-first-value (регистрация → первая AI-сессия)** | Онбординг; цель < 3 мин |

Подробные определения, воронки и пороги — в `08-metrics.md`.

## Монетизация

| Уровень | Модель | Детали |
| --- | --- | --- |
| Библиотека (B2B) | SaaS-подписка | Фиксированная плата / библиотека; тарифы по числу читателей и AI-запросов. Платёжный провайдер — ЮKassa / Tinkoff (Phase 3, см. `03-architecture-deltas.md`) |
| Читатель (B2C) | Бесплатно | AI-компаньон и клубы — бесплатно. Freemium — TBD после валидации спроса (не ранее Phase 3) |

Ранняя монетизация AI-фич для читателя — **non-goal** (`07-non-goals-and-risks.md`).

## MVP (Phase 1, ~6 недель)

Reader-facing MVP, доказывающий гипотезу AI-компаньона:

- **Витрина** (Next.js, SEO): каталог, семантический поиск, карточки книг, «похожие книги».
- **Кабинет** (Vite PWA): wishlist, история выдач, AI-чат (Recommend + explanation).
- **Сигналы**: `book.viewed`, `book.wishlisted`, `book.rated`, `ai.recommend.shown/clicked` — через `pkg/events` → schema `signals` в `book-db`.
- **Email-first уведомления**: Mailpit для E2E, существующий notification-service.
- **Telegram-бот**: опционально (не блокирует MVP).

Exit criteria — в `02-roadmap.md`.
